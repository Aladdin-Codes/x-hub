# Product

## Register

product

## Users

Individual knowledge workers in a Windows desktop environment use x-hub when they are frequently switching apps, capturing scattered ideas, and searching for local resources. The product helps them launch common tools with minimal effort, save quick notes and direct-file references, and do so without moving or renaming original files.

## Product Purpose

x-hub is a local-first personal productivity workspace that brings quick launch, speed notes, file links, and search together in a lightweight desktop window. Success means users can immediately return to the next task without memorizing paths or hunting across multiple windows; all personal data remains on the machine.

## Brand Personality

Calm, restrained, and reliable. The interface should make the user feel that the workspace is always nearby without interrupting focus: information is clear, actions are predictable, and feedback is honest.

## Anti-references

- Do not build an enterprise collaboration or project management platform: avoid complex permissions, dynamic workflows, message streams, and team metrics.
- Do not build a game-like or entertainment-focused tool: avoid decorative animation, exaggerated visuals, and attention-grabbing color.
- Do not present local management as a cloud SaaS: avoid marketing dashboards, fake sync status, or opaque data handling.

## Design Principles

1. Make the next action faster than browsing information: launch, record, open, and search should all be possible in one or two steps.
2. Local-first and privacy-aware: clearly explain data location, backup, and restore impact.
3. Familiar beats surprising: follow expected desktop software patterns and provide clear status feedback.
4. Informative but not crowded: prioritize recent and frequently used content, and reveal secondary actions progressively.
5. Be honest about broken paths and risky actions: warn early, provide reversible recovery paths, and keep the user informed.

## Accessibility & Inclusion

Use WCAG 2.1 AA as the baseline. Keyboard access should cover all primary actions, focus states should be clear, state should not rely on color alone, reduced-motion preferences should be respected, and body text and interactive controls should retain sufficient contrast.
